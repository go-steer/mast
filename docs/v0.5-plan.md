# mast v0.5 plan — unattended monitoring, and the parity claim

**Date:** 2026-08-21 · **Status:** plan, not a design decision · **Target:** close the parity claim v0.4 deferred — a scheduled cycle that collects without spending a token, learns what *changed* from [`k8s-lookout`](https://github.com/go-steer/k8s-lookout) rather than from mast logic, posts only on change through [`switchboard`](https://github.com/go-steer/switchboard), and accepts an operator ack that suppresses without pretending to be an approval

This is the continuation of [`./v0.4-plan.md`](./v0.4-plan.md), which is itself the continuation of [`./v0.3-plan.md`](./v0.3-plan.md). That first document's §1 scoreboard, §2 test tiers and §3 workstream IDs are still canonical and still the place a row is flipped; `W4.4` here is `W4.4` there. This one says which of the deferred tasks v0.5 is accountable for, gives them file anchors and exit criteria, and records the one shape decision that binds all four of them.

Like both predecessors, this is a planning artifact: decisions it surfaces belong in the owning design doc and [`./README.md`](./README.md)'s resolved-decisions table. No docs-site mirror (the roadmap page carries the user-visible half).

## 2. The shape decision that binds W4.2, W4.4, W4.5 and W4.6

All four tasks want mast to call a lookout tool. Working out *who* makes that call is not an implementation detail — it decides whether unattended monitoring is possible at all, and the four tasks are incoherent without one answer.

**The collision.** `k8s_findings_diff` declares `Writes: true` on its MCP surface, and it is right to: the diff *advances persisted state* as a side effect of answering, so a client that auto-approved it as a read would silently consume a run. mast's mutation predicate defaults every MCP tool to mutating anyway — `effects.NewPredicate`, `pkg/effects/effects.go:114`, default-deny-unknown, because ADK's `mcptoolset` drops MCP's own annotations. So under the shipped default `hitl.on_mutation: require_approval`, **a scheduled cycle that asks the model to call `k8s_findings_diff` parks for a human on every fire.** An unattended monitor that needs an approval to find out whether anything changed is not one.

**The three ways out, and why two are wrong.**

1. *Declare the un-gate* — `tool_catalog.tools[].mutating: false` on the diff. The field exists for exactly this, and its applications are audit-logged. But it would be a false declaration: the diff really does write, lookout says so, and an audited override that records a lie is worse than no override. Rejected.
2. *Use `--dry-run` for the cycle and advance state later.* This directly contradicts W4.5's ordering requirement — advance the finding state **before** notifying, so a failed Slack post does not replay the whole diff next cycle — and re-opens the exactly-once problem L1 exists to close. Rejected.
3. **The collection and state-advance legs are mast's, not the model's.** mast calls `k8s_findings_diff` itself, on its own behalf, outside the model's tool surface; the model is handed the already-classified transitions as input and never holds the tool. Nothing to gate, because no model asked for anything. **This is the answer.**

Option 3 is not a new mechanism. It is the seam [#221](https://github.com/go-steer/mast/issues/221) and v0.4's W7 already built: `cmd/mast/toolschemas.go:145`'s `read`, whose doc comment currently opens *"This is the one place mast calls a tool that no model asked for."* v0.5 makes it two places, and that comment has to change with the code — it is load-bearing prose, not decoration.

Three properties carry over from `read` and must be preserved by the new seam, because each one was learned the hard way:

- **Unwrap first.** `unwrapTool` peels `pkg/mcp`'s digesting wrap. A digest envelope on a collection result would drop the very fields the transition classification is made of and stamp a fresh call id every call — the mirror-image bug of the one that made #221's first cut void every change-set grant.
- **Refuse rather than guess.** ADK's runnable-tool interface is unexported, so the handle is asserted; a tool that does not satisfy it is reported as unrunnable rather than treated as "nothing changed".
- **State the direction of the exception in the code.** `read` is narrow because the write gate only ever passes it a tool the bundle *declared* as a precondition read, and `internal/compose` refuses to start if that tool is classified mutating. The collection seam inverts that check — it permits a mutating call precisely because it is mast's own — so it needs its own composition-time refusal to keep the exception from widening: **only tools the bundle names in a new `monitor.collect` block may be run this way**, and naming one there does not put it in any roster.

And it is what makes row 9 true by construction rather than by measurement: a leg the model is not part of cannot spend a token.

**The corollary for W4.6.** v0.3 already settled that mast must not expose an ack tool the model can call, because lookout's underlying triage-status write is not permission-gated on its side. Under option 3 that is not a rule anyone has to remember — it is the same seam. An ack arrives on the operator/transport ingress, mast attributes it, and mast forwards it. The negative test the row asks for (no ack tool in any roster) becomes an assertion about composition, not about prompt hygiene.

## 3. Workstreams

Each task: **what**, **where**, **done when**, **test**. Tasks are PR-sized. `→` marks the scoreboard rows it flips.

### W-board — Record the two rows the siblings already flipped *(no code; do it first)*

**What.** Flip rows **12** and **15** in [`./v0.3-plan.md`](./v0.3-plan.md) §1 to green, each citing the sibling commit and test that flips it (`683b5ee` / `pkg/findings/normalize_test.go`; switchboard `3964c71` / `cmd/switchboard/ingress_*_test.go`). Correct the "mast today" column for rows 11 and 13, which say *nothing at any layer* and *none* while lookout ships both halves.

**Why first.** A board that under-reports is the same defect as one that over-reports — [#174](https://github.com/go-steer/mast/issues/174)'s shape, one layer up. It also changes what the release notes can claim, and notes written against a stale board decay exactly the way the release-claims lesson says.

*Done when:* the board reads 13 of 19 with both new greens sourced.
*Test:* none — this is prose about someone else's test. Cite the test; do not re-run it here. → **12**, **15**

### W4.2 — Collection is mast's, and it costs nothing *(the seam; blocks W4.4, W4.5, W4.6)* — 🟢 **shipped 2026-08-21**

**What.** A `monitor:` block on the bundle naming the collection calls a scheduled cycle makes on mast's own behalf — `k8s_cluster_health` for the scan, `k8s_findings_diff` for the classification — and the seam in `cmd/mast` that runs them, per §2 option 3. The model is handed the result as the turn's input.

**Where.** `pkg/workload/bundle.go` (the `monitor:` block, beside `EdgeTrigger`), `cmd/mast/toolschemas.go` (the second caller of the direct-run seam; generalize `read` rather than copying it, and update its "one place" comment), `cmd/mast/schedtrigger.go` (the fire path that assembles the cycle), `internal/compose` (the refusal that keeps a `monitor.collect` name out of every roster and every allowlist).

*Done when:* a scheduled fire collects, classifies, and reaches the model with the transitions already in hand, and the meter reads zero model calls for everything before that point.
*Test:* `U-bounded-cost` gains a collection leg asserting zero model calls — **read off the meter, not inferred from latency or tokens**, the same rule W4.3 established. Plus a composition test that a `monitor.collect` tool named in a specialist allowlist is a build error. → **9**

**What shipped**, and the three places it differs from the sketch above.

- **The fence is `compose.CheckMonitorCollectSurface`** (`internal/compose/monitor.go`), on both doors — `CheckRoster` ahead of MCP wiring, and `BuildRoot` for the library path. It refuses all three ways a roster reaches a tool, not just the obvious one: naming it outright, allowing an MCP server with no `tools:` list, and declaring no `tools.mcp` key at all. The second and third are the un-enumerated grants `CheckCapabilitySplit` *exempts* a declared change executor from, which is precisely why they had to be repeated here rather than inherited.
- **The direct-run seam was generalized, not copied.** `toolschemas.go`'s `read` and the new `collect` are two thin wrappers over one `runOwnBehalf`, whose doc block names both callers, both fences, and the fact that a third caller needs a third paragraph. The "one place" comment is gone, as §2 required.
- **The collection context is hand-written** (`cmd/mast/monitorctx.go`). ADK's tool interface wants a full `agent.Context` and a collection call has no invocation to mint one from. ADK exports `ContextMock` as an embedding hook, which would have been four lines and would also mean the next ADK release to widen `agent.Context` silently hands the collection leg a nil-returning implementation of whatever was added, discovered in production. Written out, that release is a compile error. `RequestConfirmation` and `State().Set` return errors rather than nils, because a collection call that parked for a human would park forever.

Two questions §6 left open are settled by what shipped: the **cadence stays on `edge_trigger.scheduled`** and is not duplicated into `monitor:` (two places to configure one cycle, whose failure mode is that they disagree and the operator reads the one that is not running), and **a collection failure aborts the cycle before any model call**, counted as an errored fire — waking the model with a partial picture lets a monitor report calm because its collection broke, which is worse than reporting nothing because only the second is visibly broken.

### W4.4 — The transitions come from lookout, not from mast *(gated on W4.2)*

**What.** Consume `k8s_findings_diff`'s classification verbatim: `new` / `ongoing` / `escalated` / `resolved` / `suppressed`, keyed by `subject_key`. mast orchestrates, meters, gates and notifies; **it never learns what a pod is.** No mast-side fingerprinting, no mast-side severity comparison, no re-derivation of `escalated` from two severities — lookout already decided, and a second opinion here is a second source of truth.

**Where.** The cycle assembled in W4.2; a typed carrier for the transition set (mast-side, domain-neutral: a subject key, a transition string lookout owns the vocabulary of, and an opaque payload).

*Done when:* a cycle produces transitions that came out of lookout, and removing mast's own logic changes nothing because there is none.
*Test:* `U-notify-onchange` with a lookout stub, including a leg where the stub reports `escalated` for a subject whose severity mast can see did **not** change — which mast must report as escalated anyway, because the classification is not mast's to second-guess. That leg is the one that fails if anyone adds a local heuristic. → **11**

### W4.5 — Notify only on change, and advance state before you speak *(gated on W4.4)*

**What.** An egress client for switchboard's ingress: `POST /v1/messages` for the first post of a cycle, `PATCH .../append` for a timeline that grows, `PATCH` for the refinement of an assessment still in flight. Post on a non-empty transition set; digest every N cycles. **Advance the finding state before notifying** — their ordering, and the reason is that a Slack failure must not replay the whole diff next cycle.

**Where.** A new client package (zero new dependencies — the `check-slim-deps` gate stands), bearer-token config beside the existing daemon token and deliberately *not* the same value, and the cycle's tail in `cmd/mast`.

*Two things the shipped switchboard surface makes possible that the v0.3 stanza did not know about.* `append` answers **409 "send the full text"** for a message it does not remember — a restart, another replica, or a message posted from elsewhere all land there — so the client must hold the text it last sent and fall back to a full `PATCH`, not treat 409 as an error. And an append that would exceed Slack's single-message limit is posted as a threaded continuation and answered **200 with the continuation's ref**, so the client's notion of "the message I am appending to" moves; a client that ignores the 200 body will 409 forever afterwards.

*Done when:* an unchanged cycle posts nothing, a changed cycle posts once, a failed post does not resurrect the diff on the next cycle, and a digest cycle posts a summary whether or not anything changed.
*Test:* `U-notify-onchange` against a stub ingress, with legs for: no transitions → no request; transitions → one request; **post fails after state advanced → next cycle reports only what is new, not the replay**; append 409 → full-text fallback; append 200-with-ref → subsequent appends target the continuation. → **14**

### W4.6 — Ack plumbing, and an ack is not an approval *(gated on W4.2; independent of W4.5)*

**What.** An ack enters through the operator/transport ingress, mast authenticates and attributes it, and mast forwards it to `k8s_findings_ack` with `ack_by` set from the credential. lookout owns the window and the state.

**Two constraints that bind the implementation**, both settled 2026-08-12 in [`./orchestration-design.md`](./orchestration-design.md) "Ack routing" and neither re-openable here:

- **An ack is not a mutation approval.** No grant, no `approve | reject | edit` verdict, no freshness window, no change-set signature. Reusing the write gate's machinery would put an ack in the decision export as if it were an adjudication, and [#194](https://github.com/go-steer/mast/issues/194)'s work on who-approved-what would start attributing suppressions as approvals.
- **mast must not expose an ack tool the model can call.** Under §2 this is structural: the ack is a `monitor.collect`-class call, so no roster can hold it.

`ack_by` is read from the credential at the moment of the request, never from the request body — the same rule #194 settled for `ConsumedBy`, and for the same reason: an attribution a caller writes about itself is worth nothing after an incident.

*Done when:* an ack is attributed to a real identity in mast's audit log, suppresses in lookout, and the next cycle reports the subject as `suppressed` because lookout says so.
*Test:* `U-ack`, plus the negative assertion that no ack tool appears in any workload's tool roster, plus an attribution test that a body-supplied `ack_by` is ignored in favour of the credential. → **13**

### W6.2 / W6.3 — switchboard's half *(not this repo; wire-contract tests are)*

Owned by switchboard: `EventTypeInteractive` / `block_actions` mapped onto mast's resume endpoint and the ack endpoint (W6.2 → rows **16**, **13**), and the approver allowlist asserted through `X-Asserted-Caller` (W6.3 → row **17**).

mast's accountability is that the contract switchboard codes against does not move under it, and that the identity it asserts arrives where #194 put it. That is a test in this repo — `pkg/inject`'s resume shape and the `auth.Attribution` path — not a feature.

## 5. Scope

**In:** W-board, W4.2, W4.4, W4.5, W4.6, and the mast-side wire-contract tests for W6.2/W6.3.

**Deliberately not in v0.5**, each for a stated reason rather than by omission:

- **Multi-cluster acks.** lookout's multi-cluster path is in-memory, so an ack would evaporate on restart. Named as a follow-on against [k8s-lookout#208](https://github.com/go-steer/k8s-lookout/issues/208) by the W5 stanza; single-cluster and durable is the MVP, and pretending otherwise would ship a suppression that silently stops suppressing.
- **A `Finding` or `HealthReport` Go type in mast.** The 2026-08-12 assessment closed this: the boundary is a wire contract, not a Go import, and a domain-aware type here would be the first one in the substrate. W4.4's carrier is a subject key, an opaque transition string and an opaque payload for exactly this reason.
- **Golden-trace replay for all 31 scenarios.** Still worth doing for the ~8 anchor scenarios only, on [`./v0.3-plan.md`](./v0.3-plan.md) §2's argument; the trajectories have not stopped churning.
- **Any re-proposal of a `pkg/digest` LLM fallback.** [#221](https://github.com/go-steer/mast/issues/221) shipped structural-only and hardened core-agent `3de4134`'s verdict into "lands with an LLM fallback or not at all". That is a decision, not an invitation.

## 6. Carried-in open items

These are not v0.5 workstreams. They are the things a v0.5 session will trip over, listed so it does not have to rediscover them.

- **[#235](https://github.com/go-steer/mast/issues/235) — a planner-dispatched specialist's mutating calls bypass the write gate and the effect outbox.** Contained 2026-08-21 by `compose.CheckPlannerWriteSurface`, which refuses the combination at composition on both doors. **Containment is not the fix**, and the check's own doc comment says it comes out with whichever boundary decision lands. That decision — host session service for the sub-run, gate at the dispatch boundary, or keep the refusal permanently — needs a human. **It touches v0.5 directly:** a monitoring bundle that grows a planner is exactly the shape the refusal now blocks.
- **[#98](https://github.com/go-steer/mast/issues/98) — the remaining AG-UI slices.** Six deferred slices, none blocking parity. Two of them (per-key `StateDelta`, client-disconnect reconnect) are self-contained; two (client-declared tool acceptance, activity/reasoning events) need an acceptance policy decided first.
- **[#178](https://github.com/go-steer/mast/issues/178) is closed but its defect is live.** `compose.RatePer1K` still keys on model id alone (`internal/compose/compose.go:579`), so `anthropic-vertex` is priced off the first-party Anthropic table though Claude on Vertex is partner-priced. Closed 2026-08-18 as absorbed into [`./model-support-design.md`](./model-support-design.md)'s M2 slice; whoever ships M2 owns it. Do not fix it sideways.
- **The watchdog governance call.** `NewDominantToolCallSignal` shipped undefaulted ([#227](https://github.com/go-steer/mast/issues/227)) and a test fails if `NewDefaultWatchdog` starts wiring it without the docs changing. Whether it joins the default set is unanswered. A scheduled monitoring loop is precisely the workload the default posture was softened for — see `Bundle.Watchdog`'s own comment about a daemon watching a rollout settle — so v0.5 has an opinion to contribute here even if it does not make the call.
- **Two upstream questions with no owner:** park-on-interrupt semantics (`6c2c5c8` / `0a6a056`, colliding with what [#206](https://github.com/go-steer/mast/issues/206) documented), and whether ADK-installed dispatch tools should meet the permissions gate (`32aed49`).
- **The GKE WIF IAM narrowing is untested live.** `WRITE_SCOPE=namespaced` ships opt-in because the WIF-principal → RBAC-subject mapping has never been verified on a real cluster. A decision, not a defect; it needs a cluster, not a PR.
