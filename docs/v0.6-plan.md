# mast v0.6 plan — enforcement that reaches, and a ceiling that stops a call

**Date:** 2026-08-30 · **Status:** plan, not a design decision · **Target:** close the two places where mast's enforcement is weaker than the bundle says it is — a mutating call inside a planner dispatch that no gate sees, and a budget ceiling that is crossed by the call that reports it

This is the continuation of [`./v0.5-plan.md`](./v0.5-plan.md), which continues [`./v0.4-plan.md`](./v0.4-plan.md) and [`./v0.3-plan.md`](./v0.3-plan.md). That first document's §2 test tiers and §3 workstream IDs are still canonical; this plan opens **W9** and **W10**, the first IDs since W8.

Like its predecessors this is a planning artifact: decisions it surfaces belong in the owning design doc and [`./README.md`](./README.md)'s resolved-decisions table. No docs-site mirror — the roadmap page carries the user-visible half.

## 0. The scoreboard no longer supplies a spine

v0.3, v0.4 and v0.5 were all organized by the same thing: the parity scoreboard in [`./v0.3-plan.md`](./v0.3-plan.md) §1. Pick the red rows, flip them, ship. That spine is spent. The board reads **17 of 19** at the v0.5.0 tag, and the two rows still red — in-chat Approve/Reject and the approver allowlist — are [switchboard's](https://github.com/go-steer/switchboard/issues/40) [to write](https://github.com/go-steer/switchboard/issues/65). mast's side of them shipped in #248 as a wire-contract test.

**v0.6 is the first release since the fork that has to state its own claim.** The board will not choose for us, and "whatever is left in `Further out`" is a backlog, not a release. So this plan starts by naming the claim and defending it, rather than by listing rows.

The scoreboard stays where it is and stays canonical for parity. It simply stops being the agenda.

## 1. The claim

> **Enforcement reaches every call the workload makes, and a ceiling stops a call before it is paid for.**

Two gaps sit behind that sentence, and both have the same shape from an operator's chair: *the bundle says something that the runtime does not fully deliver.*

**(a) A mutating call inside a planner dispatch is seen by no gate.** `invoke_specialist` constructs its runner in the tool body with no plugins, so neither the effect outbox nor the write gate reaches a call the dispatched specialist makes. Measured, not inferred — an outer `BeforeToolCallback` over that shape sees `invoke_specialist` and `finish_task` and never the `scale_deployment` executed between them ([#235](https://github.com/go-steer/mast/issues/235)). Contained since #237 by refusing the combination at composition, which closes the silent-violation path and does not close the hole.

**(b) A ceiling is crossed by the call that reports it.** `budget.Meter.Observe` folds usage out of the event stream after a call returns, so the first thing that happens when a workload runs out of money is that it spends more money. And a crossed *specialist* ceiling stops the session rather than handing the coordinator a refusal it could route around, which turns a per-specialist cap into a session-killer.

Neither is a bug in the sense that something reports the wrong answer. Both are cases where a bundle's `hitl.on_mutation` or `budget.max_usd` promises an operator more than the runtime enforces — which is the specific failure this product exists to not have.

### What this release is not

Not parity. Not a new surface. Nothing here adds a tool, a bundle block a user must learn, or an endpoint. If v0.6 ships correctly, an existing bundle behaves the way its author already believed it did, and one composition refusal disappears.

## 2. The seam inventory, and the premise this plan had to abandon

The [roadmap](https://go-steer.github.io/mast/roadmap/) says of pre-call budget gating: *"Both need a seam in front of the model call rather than behind it."* It is easy to read "both" as *#235 and budget*, and to conclude the two are one piece of work. **They are not, and this plan was drafted on that wrong premise before it was traced.** The "both" in that sentence is budget's own two problems. Recording the correction here so it is not re-derived:

| Concern | Mechanism today | File | Crosses a planner dispatch? |
|---|---|---|---|
| Effect outbox | runner plugin, `BeforeToolCallback` | `pkg/effects/effects.go:274` | **No** |
| Write gate | runner plugin, `BeforeToolCallback` | `pkg/approval/plugin.go:141` | **No** |
| Spend metering | folds `session.Event`s in the **caller's event loop** | `pkg/budget/budget.go:226`, installed at `mast.go:636`, `cmd/mast/main.go:2755`, `cmd/mast/subrun.go:173` | **Yes**, via `SubRunSink` |
| Watchdog | same out-of-band channel | `cmd/mast/subrun.go:192` | **Yes** |

They are different mechanisms in different layers. The plugins are runner-scoped and the sub-runner at `pkg/planner/dispatch.go:284` is constructed with no `PluginConfig`. Metering is not a plugin at all, and is post-hoc *by construction* — `Observe` can only see usage that a returned event already reports.

So **v0.6 is two workstreams that ship under one claim, not one piece of work.** Saying so up front is cheaper than discovering it in the third PR.

### The transfer that is real

`pkg/planner/dispatch.go:256` states the useful fact in its own words:

> *"The inner runner's accounting reaches the host through `obs` (#226). Its PLUGINS do not, and that is the larger hole on the same seam."*

That is standing proof that **a host-owned concern can cross the dispatch boundary without being a plugin.** #235's option 1 is currently framed as "give the sub-run the host's session service under a derived id," which buys durability at the cost of the context isolation the private sub-session exists to provide. `SubRunSink` suggests a fourth option that was not in the issue: carry the *gate decision* out-of-band the way spend already travels, and leave the sub-session alone. W9.1 exists to decide between them.

### The third seam, for W10

A `model.LLM` wrapper travels with the model object rather than with the runner, so it reaches a dispatched specialist for free. The shape is already proven in this codebase — `internal/evals/judge/retry.go:107` wraps `adkmodel.LLM` to retry a provider's 429/503 — but only in evals. The production construction point is `internal/compose.BuildModel` (`internal/compose/compose.go:507`). That is the natural home for a check that must run *before* a call is issued, and W10.1 should weigh it against an `llmagent` `BeforeModelCallback`.

## 3. Tasks

Six, one PR each. Two chains, and they do not block each other — W9 and W10 can run in parallel.

### W9 — The gate reaches a dispatched call

- [ ] **W9.1 — decide the boundary** *(design; blocks W9.2)*. Weigh four shapes against each other, in writing, and record the outcome in [`./README.md`](./README.md)'s resolved-decisions table: (1) host session service under a derived id + install the plugins; (2) gate at the dispatch boundary, approving `invoke_specialist` itself when the target is a change executor; (3) keep the refusal permanently; (4) **new** — carry the gate decision out-of-band through the `SubRunSink` channel that spend and the watchdog already use, leaving the sub-session in-memory. The park problem is the discriminator: an approval park suspends a turn to be resumed from a durable session, and a dispatch's sub-session dies with the tool call. Exit criterion is a decision with a named owner and a defensible answer to *"what does a park inside a dispatch resume into?"* — not a preference.

- [ ] **W9.2 — implement it, and delete the containment** *(gated on W9.1)*. Whichever shape wins, `compose.CheckPlannerWriteSurface` comes out with it; its doc comment already promises this, which is why it cannot quietly become the permanent answer. Test: the #235 probe becomes a regression test — an outer plugin chain over a planner root with a `change_executor` must see the mutating call, and it must fail on pre-fix code. Plus a park-and-resume leg through a dispatch, because that is the half a wiring change alone does not buy.

- [ ] **W9.3 — the outbox record, under `apply` too** *(gated on W9.1)*. The refusal exempts `on_mutation: apply` because there was no gate to bypass, but the missing outbox record is real there and costs exactly-once replay after an interrupted dispatch. This is the leg an unattended monitor actually needs, since `apply` is what an unattended workload sets when nobody is there to approve. Test: kill a dispatch mid-mutation and assert a dangling intent is scannable and the completion replays.

### W10 — A ceiling stops a call before it is paid for

- [ ] **W10.1 — pick the pre-call seam** *(design + spike; blocks W10.2)*. `model.LLM` wrapper at `compose.BuildModel` versus an `llmagent` `BeforeModelCallback`. The wrapper travels with the model and therefore reaches a dispatched specialist for free; the callback is agent-scoped and needs checking against the dispatch path. Decide, and say what a refusal *looks like* to the caller — an error, a synthesized response, or a cancel — because that choice is what W10.3 depends on.

- [ ] **W10.2 — refuse the call that would cross the ceiling** *(gated on W10.1)*. Keep the existing post-hoc fold: it is the ledger and it is durable (#175), and a call that crossed still cost what it cost. Add the pre-call check in front of it. Test: a workload one call away from its cap makes **zero** further model calls, read off the meter rather than inferred, and the ledger shows no phantom spend for the refused call.

- [ ] **W10.3 — a crossed specialist ceiling is a refusal, not a session stop** *(gated on W10.2)*. Today the coordinator loses the session; it should get a refusal it can route around, the same way it handles a specialist that declines. Test: a roster where one specialist's cap trips must complete the workload through another path, with the trip visible on the meter and in the transcript.

**Board impact: none.** No parity row moves — all six of these are behind rows that are already green, which is exactly why the board could not have chosen this release.

## 4. Decisions this release has to make

- **What a park inside a dispatch resumes into** (W9.1). The whole boundary question reduces to this. If there is no defensible answer, option 2 (gate the dispatch boundary itself) wins by default, and the plan should say that out loud rather than letting option 1 win on aesthetics.
- **Whether one answer authorizing a whole specialist is an approval or a blank cheque** (W9.1). Option 2's cost: the operator approves `invoke_specialist`, and every mutating call that specialist then makes is covered. That is a weaker promise than the write gate makes everywhere else, and L7 — *approval bound to a typed change set* — is the lead row it puts pressure on.
- **What a pre-call refusal looks like to the model** (W10.1). An error the model sees and can react to, versus a cancel it cannot. The first is more useful and is also a new way for a workload to talk itself into a loop; the watchdog is the thing that would catch that, which is the next bullet.
- **Whether the dominant-tool-call detector joins the default set** ([#227](https://github.com/go-steer/mast/issues/227), carried from v0.5, which had an opinion and did not make the call). v0.6 adds a refusal a model can loop against, so this release has a better reason to decide than v0.5 did.
