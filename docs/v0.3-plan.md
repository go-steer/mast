**Date:** 2026-08-12 · **Status:** plan, not a design decision · **Target:** the functional equivalent of [`langchain-ai/sre-agent`](https://github.com/langchain-ai/sre-agent), spanning `mast`, [`k8s-lookout`](https://github.com/go-steer/k8s-lookout), and [`switchboard`](https://github.com/go-steer/switchboard)

This is the executable form of the six-slice plan in [`./assessments/langchain-sre-agent.md`](./assessments/langchain-sre-agent.md) §4. That doc argues *what* the gaps are; this one is the work breakdown — PR-sized tasks with file anchors, a definition of done, and the test that proves each one. Task IDs (`W1.2`) are stable and file directly as issues.

Like the assessment and [`./uat-v0.2-plan.md`](./uat-v0.2-plan.md), this is a planning artifact: decisions it surfaces belong in the owning design doc and [`./README.md`](./README.md)'s resolved-decisions table. No docs-site mirror.

## 0. One deliberate change from the assessment's sequencing

The assessment put evals last (P5, "gates everything after"). **Invert it.** The eval harness lands *first*, in W0, as a scoreboard that starts almost entirely red.

The reason is not process aesthetics. "How do we compare to LangChain?" is not answerable by reading diffs — it needs a measurement that exists before the work does, so each workstream can be scored against a fixed baseline rather than against a target that moves as we learn what we built. Building the measuring stick last means the first honest comparison happens after the last PR, which is the wrong time to discover a gap.

Cost objection doesn't hold: three of the four test tiers are free (§2), and the metered tier is roughly **$5–15 per nightly run** across 31 scenarios. That is not a number worth sequencing around.

## 2. Test strategy — four tiers

The assessment's §5 proposed two tiers and **claimed the deterministic tier could gate `tool_coverage`**. That is wrong, and correcting it is load-bearing for this plan.

`tool_coverage` measures *which tools the model chose*. A scripted provider or `toolactor` does not choose — its trajectory is the fixture. Replaying a scripted trajectory and asserting the tools match the script asserts that the script equals itself. **Measuring agent quality, and therefore comparing to LangChain at all, requires a live model.** What the free tiers gate is *mast's guarantees*, which is a different and equally necessary thing.

| Tier | What it proves | Provider | Cost | Cadence | Harness |
|---|---|---|---|---|---|
| **S — smoke** | it builds and runs offline | echo | zero | every PR | `go test` + per-starter `main.go` run (the `scripts/demo-spike2.sh` bar) |
| **U — UAT** | the *system* behaves: routing, gating, metering, crash/resume, HTTP contract | `scripted` / `toolactor` | zero | every PR | `scripts/uat-v0.3.sh` → `dev/ci/presubmits/e2e.sh` |
| **E — deterministic eval** | mast's *differentiators* hold under adversarial trajectories: exactly-once, refusal, rejection, budget, edit-application | `scripted` / `toolactor` | zero | every PR | `scripts/evals.sh` → `dev/ci/presubmits/evals.sh` |
| **J — judge / live** | *agent quality*, and the only LangChain-comparable numbers | real provider | ~$5–15/run | nightly + pre-release | same harness, `--tier=judge` |

Tiers S/U/E are gates: red blocks the PR. Tier J is a **report**, not a gate — a judge score is too noisy to block on, and gating on it invites tuning the judge. It posts a scoreboard delta.

**Golden-trace replay** sits between E and J: capture one real trajectory per scenario (metered, manual, `mast sessions capture-golden` per [`./orchestration-design.md`](./orchestration-design.md)), commit it, replay free forever after. It catches *harness* regressions against a frozen model decision — not model regressions. Worth doing for the ~8 scenarios in the anchor workload; not worth doing for all 31 until the trajectories stop churning.

**Naming.** Tests referenced in the scoreboard use their tier prefix: `U-gate-crash`, `E-approval-edited`, `J-severity-accuracy`.

**Conventions inherited from the v0.2 UAT** (non-negotiable, see [`./uat-v0.2-plan.md`](./uat-v0.2-plan.md) "Harness shape"): deterministic, credential-free, offline; real SQLite `--session-db` for anything crossing a restart; state under `${TMPDIR:-/tmp}/...` (house rule #5); `set -euo pipefail` + `trap cleanup EXIT`; bounded `wait_for` polls, never bare sleeps; every new script wired into `dev/ci/presubmits/all.sh` *and* `.github/workflows/ci.yml` so local == CI (house rule #6).

> **Three decisions this workstream had to make that the plan did not name.** Recording them here because W0.4's allowlist and W0.5's reporting both depend on them.
>
> - **A vacuous 1.0 is marked, not hidden.** Upstream's `tool_coverage` is 1.0 on all 31 rows because there is nothing to measure, and nothing in its output distinguishes that from a perfect run. Every `Result` therefore carries `Vacuous`, set when the score is 1.0 for want of anything to score — no expected tools, no expected severity, no mutating effects. W0.4 should treat a wholly-vacuous corpus as a harness failure, not a green board.
> - **The severity extractor is deliberately not upstream's, in both directions.** Upstream's bracketed `\[(CRITICAL|WARNING|INFO|OK)\]` matches 0 of 31 expected responses. mast's reads the expected side the way the corpus is actually written (bare leading token) and accepts on the actual side the forms a model plausibly emits for the same claim — `CRITICAL:`, `[CRITICAL]`, `**CRITICAL**`, `## CRITICAL`, `Severity: CRITICAL`. It stays anchored to a line start: an unanchored search scores "nothing critical was found" as a CRITICAL verdict. `TestSeverityAccuracy_CorpusIsReadable` is the standing guard that the extractor has not silently become a constant.
> - **`exactly_once` keys on tool name plus canonicalized arguments, not call ID.** Scaling two different deployments is two effects; scaling one deployment twice is the violation. Keying on the ID would make the metric structurally incapable of failing, which is the exact failure mode found in upstream's harness.

> **Divergence from `pkg/effects`, on purpose.** `pairScan` *defers* long-running calls, because at turn start the runtime has not yet decided whether they ran. An evaluator scores a finished run, where a long-running call that completed is an effect like any other — deferring it would blind `exactly_once` to a re-fired blocking tool, which is the failure it exists to catch. This is the one place the two walks differ, and `TestTraceFromEvents_Exclusions/long-running-calls-are-kept` pins it.

### W2 — The write gate, `per_call` *(mast; assessment P1 — the long pole)*

Granularity is settled (resolved Q3): both `per_call` and `per_change_set`, **one gate not two**, `per_call` first and UAT-green before `per_change_set` starts (that's W7).

**W2.1 — Wire `pkg/permissions` into the tool-execution seam.** The seam is proven — `pkg/effects` registers as a runner plugin at `cmd/mast/main.go:443` and `cmd/mast/oneshot.go:127`. Today **no `permissions.Gate` is constructed anywhere in non-test code**; only `pkg/attach/prompter.go` imports the package. Ordering is settled: outbox check *then* gate (a replayed result needs no fresh approval — resolved-decision row 144).
*Done when:* a gate is interposed on tool execution and its prompts reach an operator over the existing `PromptBroker`.
*Test:* `U-gate-percall`. → **4**

**W2.2 — Implement `hitl_policy.on_mutation`** (`require_approval` / `apply` / `dry_run`) against the documented mutation predicate: built-in annotation + MCP `readOnlyHint`, default-deny-unknown, per-tool audited override via `tool_catalog.tools[].mutating` (`pkg/workload/bundle.go:64-74`). Note the shipped finding that ADK's mcptoolset **drops MCP annotations**, so the override is the real un-gate in practice.
*Done when:* a mutating call parks the turn *before* it fires, survives `kill -9`, and resumes on approval.
*Test:* `U-gate-crash`, `E-exactly-once`. → **4**, **5**, **L1**

**W2.3 — Restrict grant scopes for mutating tools.** Normative, and it must land **with** W2.1, not after. `AllowOnce` plus change-set-minted exact-signature grants only; `AllowSessionVerb` / `AllowSessionTool` / `AllowAlways` refused. The ported scopes are developer-tool ergonomics: `AllowSessionTool` on `patch_resource` hands over the namespace for a session.
*Done when:* requesting a session-wide scope on a mutating tool is refused at the gate, audited.
*Test:* unit + `U-gate-scopes` (assert the refusal, and that it is not bypassable via `ModeYolo`). → **4**

**W2.4 — Split the roster by capability.** Analyst specialists get read-only allowlists; one `change-executor`-shaped specialist holds writes. Strip `patch_resource` / `rollout_undo` from `OOMKilled.tmpl` and its siblings, which today are held back only by prompt text at lines 34-38 (*"Do NOT mutate anything on your own initiative"*) — precisely the boundary LangChain rejected.
*Done when:* a diagnosis specialist structurally cannot mutate, and a bundle that gives one a write tool fails to load.
*Test:* `U-gate-structural`. → **3**

**W2.5 — Extend the verdict to `{approve | reject | edit}`** with edited arguments validated against the tool's input schema. Copy their legibility rule: narrow, named tools only — nothing with `helm upgrade`-shaped blast radius, because an operator cannot approve what they cannot read.
*Done when:* an operator's edited arguments are the ones that execute, and a rejection stops the agent.
*Test:* `E-approval-edited`, `E-approval-rejected`. → **6**

**W2.6 — RBAC mirror** in `deploy/base`: cluster-wide read ClusterRole, namespace-scoped write Role. An increment on the existing daemon/watcher service-account split, not a new pattern.
*Done when:* the write Role is namespace-scoped in the manifests.
*Test:* manifest lint + a documented manual `kubectl auth can-i` matrix.

*Exit for W2:* a diagnosis specialist structurally cannot mutate; a remediation call parks *before* firing, survives `kill -9`, and resumes with the operator's edits applied. **UAT green here is the gate on W7 starting.**

### W3 — Fan-out *(mast; assessment P2; depends on W1.3)*

**W3.1 — `dispatch: fanout` graph shape.** Narrower and faster than the full `run_shape_fan_out_fan_in`: N cheap-tier analysts concurrent, one frontier-tier synthesis node merging to a single report. Concurrency capped at the `NewParallelWorker` `maxConcurrency` argument — the one that actually binds from a workflowagent root (resolved-decision row 133; `WithMaxConcurrency` is unreachable there). Each branch budget-bounded. Remediation stays sequential and post-synthesis.
*Done when:* "audit namespace X" produces one merged report from concurrent analysts.
*Test:* `U-fanout`. → **7**

**W3.2 — Synthesis reads branch `Output` payloads only.** Carried in from resolved Q5: ADK discards every branch-internal tool event (`runWrappedOnce` keeps only `extractOutput` hits; the worker emits `&session.Event{Output: output}` with no `Content`), so a branch's payload is its only durable record. Any proposed mutation from a `dry_run` analyst must be returned there.
*Done when:* the synthesis contract documents and enforces payload-only input.
*Test:* `U-fanout-payload` — a branch that writes a tool event and returns nothing yields an empty synthesis, asserted deliberately.

**W3.3 — Refuse mutating tools in a parallel branch's allowlist, at construction.** Small increment on W2.2's predicate. Prose is not enough: a mutation inside a branch is invisible to crash recovery, so the session looks clean when it isn't — worse than being outside outbox coverage. See [`./workflow-scaffolding-design.md`](./workflow-scaffolding-design.md), "Parallel branches are invisible to the event log."
*Done when:* a bundle that puts a write tool on a fan-out analyst fails to build.
*Test:* `U-fanout-refuse`. → **3**

### W4 — Proactive monitoring, mast side *(assessment P3; depends on W1.3, W1.4; pairs with W5)*

**W4.1 — `scheduled:` on `EdgeTrigger`** (interval + jitter). `pkg/workload/bundle.go:121-126` already says *"other transports (message queue, scheduled) will join here."* Reuse the timed-pause scheduler in `cmd/mast/pausesched.go` (`push` / `earliest` / `fireDue` / `seed` — it already survives restart via the transcript store).
*Done when:* a bundle fires on an interval and the schedule survives a daemon restart.
*Test:* `U-scheduled`. → **8**

**W4.2 — Collector = `k8s-lookout`.** `lookout health --format=json` plus `triage delta` / `triage top` over lookout's MCP mode. Zero model tokens.
*Done when:* a scheduled run collects with no model call.
*Test:* `U-bounded-cost` asserts zero tokens on the collection leg. → **9**

**W4.3 — Bounded analysis path.** One cheap-tier call, forced structured output, no orchestrator, fixed step count. Their strongest lesson; nearly free once W1.3 lands.
*Done when:* a scheduled cycle costs one model call, and the count is asserted not estimated.
*Test:* `U-bounded-cost`. → **10**

**W4.4 — Wire the lookout diff.** Shell/MCP call to `lookout findings diff --report -` (W5), consuming the transition classification. Mast orchestrates, meters, gates, and notifies; **it never learns what a pod is.**
*Done when:* a cycle produces new/ongoing/resolved transitions from lookout, not from mast logic.
*Test:* `U-notify-onchange` with a lookout stub. → **11**

**W4.5 — Notify only on change, digest every N. Advance finding state *before* notifying** — their ordering, and it matters: a Slack failure must not replay the whole diff next cycle.
*Done when:* an unchanged cycle posts nothing; a failed post does not resurrect the diff.
*Test:* `U-notify-onchange` includes a post-failure leg. → **14**

**W4.6 — Ack plumbing.** Acks traverse mast for authn and audit and are forwarded to lookout, which owns the state. Settled 2026-08-12 — see [`./orchestration-design.md`](./orchestration-design.md) "Ack routing"; no decision left to make here. Two constraints that bind the implementation: an ack is **not** a mutation approval (no grant, no `approve | reject | edit` verdict, no freshness window), and mast must **not** expose an ack tool the model can call — acks enter through the operator/transport ingress only, because lookout's underlying triage-status write is not permission-gated on its side.
*Done when:* an ack is attributed in mast's audit log and suppresses in lookout.
*Test:* `U-ack`, plus a negative assertion that no ack tool appears in a workload's tool roster. → **13**

### W5 — Finding state *(k8s-lookout; [go-steer/k8s-lookout#212](https://github.com/go-steer/k8s-lookout/issues/212); parallelizable)*

Owned by the lookout issue; summarized here because W4.4 blocks on it. Run-to-run transition surface (`new`/`ongoing`/`escalated`/`resolved`/`suppressed`), a **normalized subject key** distinct from the frozen class-grain `engine.Fingerprint` (which must not be widened — it deliberately excludes the affected object and is a cross-cluster contract), a port of `normalize_resource_name`, ack windows, and the `lookout findings diff --report -` surface. Built by generalizing the §9.1 occurrence store, not by adding a tracker beside it. **Single-cluster and durable for the MVP**; multi-cluster is in-memory today, so acks would evaporate on restart — a named follow-on against lookout #208, not an MVP assumption. → **11**, **12**, **13**

### W6 — Slack *(switchboard; assessment P4; parallelizable)*

**W6.1 — `POST /notify`** — agent-initiated post to a channel, rendering the report through the existing Block Kit layer (`pkg/chat/slack/blockkit.go`, `mrkdwn.go` already render). Unattended monitoring requires this by definition: there is no thread to reply into. → **15**

**W6.2 — `EventTypeInteractive`.** `pkg/chat/slack/slack.go:152-174` dispatches `Connecting`/`Connected`/`ConnectionError`/`EventsAPI`/`SlashCommand` and no interactive events, so no `block_actions`, so no buttons. Map `block_actions` → mast's resume endpoint (`pkg/inject`'s `ResumeRequest` takes session + interrupt, or a token) and → the ack endpoint. → **16**, **13**

**W6.3 — Approver allowlist**, asserted through the existing `X-Asserted-Caller` path so mast attributes the decision to a real human in the audit log. → **17**

*Verify unchanged:* mast's attach server already serves the daemon contract switchboard speaks (`pkg/attach/handlers.go:232-270` — `POST /sessions`, `/sessions/{sid}/inject`, `/wake`, `/interrupt`, SSE `/events`).

### W7 — `per_change_set` *(mast; gated on W2 UAT green)*

A grant-minting path **in front of** the W2 gate, not a second mechanism: mint N grants bound to exact normalized `(tool, arguments)` signatures, which the per-call gate consumes silently. Durable minted-not-chosen grants on the resume-token pattern, consumption paired against the outbox record, plus the freshness bound and precondition re-check the approval window demands, plus the legibility rule.
*Exit:* an operator approves N mutations once; a crash after call 3 of 5 resumes knowing which fired and re-fires none; a stale change set is refused back to the operator rather than silently applied.
*Test:* `U-changeset-crash`, `U-changeset-stale`.

### W8 — Decision feedback loop *(mast; falls out of W2.5)*

Log every approve / reject / edit verdict as a labeled eval example. *"Human edited 10 replicas → 4"* is the highest-signal data the system produces and it arrives free once the verdict is richer than a boolean.
*Test:* `E-feedback-capture`. → **19**

## 5. Scope

**Recommended v0.3 = M1–M4.** That is the parity claim, and it is the smallest set that supports it: drop W4 or W6 and the thing is not autonomous; drop W2 and it is not safe to make autonomous.

**M5 (W7, W8) is stretch.** Both are genuinely valuable and neither is required for parity. If v0.3 is running long, they slip to v0.4 without weakening the release story — say so in the release notes rather than shipping W7 half-gated.

For calibration: v0.2 shipped 11 issues. M1–M4 is roughly 24 tasks across three repos, of which ~16 are in mast. This is a larger release than v0.2. If that is not the intended shape, the natural cut is **v0.3 = M1–M3** (safe + capable, mast-only) and **v0.4 = M4–M5** (unattended, cross-repo) — the scoreboard makes either framing honest, because it reports what is actually green.

**Explicitly not in v0.3:** the AG-UI remaining slices ([#98](https://github.com/go-steer/mast/issues/98)) unless they land independently; multi-session substrate; durable multi-cluster finding state; the remaining five workflow starters; per-branch cost attribution beyond what W1.1 needs.
